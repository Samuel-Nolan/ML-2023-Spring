05 / Transfer to LLM

骨架相同，内部结构不同

不要用“MLP 很小，所以与 LLM 无关”来理解这份代码。更有效的问法是：哪些训练机制原样保留，哪些组件必须替换？

先掌握闭环，再替换组件。
规模变化，不会让训练的基本原则失效。

从这份 notebook 迁移到 LLM 时，损失函数、网络结构与数据表示发生根本变化；而可复现、训练/验证隔离、最佳 checkpoint 与早停等工程原则仍然成立。

训练骨架这份 NotebookLLM 中的对应物为什么变化
样本抽象接口保留COVID19Dataset
返回 x, y		TokenDataset 返回 input_ids、attention_mask、labels语言模型处理变长 token 序列，需要掩码与位移标签。
数据变换需要替换select_feat
手工选择表格列		Tokenizer、packing、truncation、DistributedSampler文本不是固定列；预训练更关注 token 化、序列拼接与多卡切分。
模型前向结构替换Linear → ReLU → Linear
[B,88] → [B]		Embedding + Transformer blocks + LM headMLP 拟合表格映射；Transformer 建模序列上下文并输出词表 logits。
损失函数目标替换MSELoss
连续值回归		CrossEntropyLoss
next-token prediction		回归拟合数值；语言建模是在词表类别上预测下一个 token。
参数优化闭环保留SGD + momentum
zero_grad / backward / step		AdamW + scheduler + grad clip + accumulation三步闭环不变；大模型需要更稳定、更节省显存的优化策略。
验证与保存原则保留eval / no_grad
best_loss / early_stop		validation perplexity、checkpoint、resume验证不参与反向传播、保存最佳状态的原则完全一致。
推理导出流程扩展predict → pred.csvgenerate → sampling → tokenizer.decode从一次性数值预测扩展为自回归、多步 token 生成。
